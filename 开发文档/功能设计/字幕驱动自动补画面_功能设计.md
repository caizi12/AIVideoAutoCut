# 字幕驱动自动补画面功能设计文档

- **功能名称**：字幕驱动自动补画面 / 自动 B-roll 素材匹配与合成
- **所属模块**：自动字幕、素材管理、视频合成
- **目标版本**：优先作为 v2.x 增强功能落地，能力稳定后并入 v3.0 专业剪辑流程
- **建议周期**：MVP 2-3 周，可编辑增强版再追加 2-4 周
- **当前状态**：待确认需求边界后进入实现
- **关联主文档**：[JJYB_AI智剪_完整开发文档_Part3.md](../JJYB_AI智剪_完整开发文档_Part3.md)
- **更新日期**：2026-05-27

## 1. 需求背景

当前字幕工具已经具备视频上传、ASR 自动字幕、字幕样式编辑、字幕渲染导出、项目记录恢复等能力。新需求是在“固定图片 + 配音”的 MP4 场景下，先识别配音字幕，再根据字幕语义自动搜索免费公开视频素材，按字幕时间轴剪辑并合成为一个画面更丰富的新视频。

该能力本质上不是单独的字幕功能，也不是纯视频转码功能，而是一个基于字幕结果的业务编排流程：字幕识别提供时间轴和语义线索，公开视频素材服务提供候选 B-roll，合成引擎负责把候选片段按时间轴替换或覆盖原始静态画面。

---

## 2. 功能目标与非目标

### 2.1 核心目标

- 从现有字幕项目中读取字幕段落、原视频、字幕样式和项目状态。
- 将字幕按语义和时长切分为镜头计划，生成每个镜头的搜索关键词、画面意图、时长、比例和优先级。
- 接入 Pexels、Pixabay 等公开或各种免费素材源，按镜头计划搜索公开视频候选。
- 下载、缓存、转码候选素材，按字幕时间轴自动裁剪并合成新视频。
- 保留原始配音音轨，可选保留字幕烧录或导出无字幕版本。
- 在项目结果中保存镜头计划、素材来源、作者、许可、原始链接、下载路径和合成结果，便于追溯,用户也可以方便清晰的知道抓取到的素材信息
- 功能上所有的操作可以自动保存状态和进度，用户可恢复工作。

### 2.2 明确非目标

- MVP 不承诺素材语义 100% 精准，只提供“自动搜索 + 可替换”的半自动工作流。
- MVP 不做复杂多轨时间线编辑器，只围绕字幕段落生成单视频轨 B-roll。
- MVP 不强依赖 CLIP、YOLO 等本地视觉模型；这些能力可作为后续语义重排和质量评分增强。

## 3. 素材边界


每条远程素材候选至少保存以下信息：

- `provider`：素材源，例如 `pexels`、`pixabay`,等其它可以搜索的公开素材源。
- `source_id`：素材源内部 ID。
- `source_url`：素材原始页面链接。
- `author`：作者或上传者。
- `license`：素材源返回或平台声明的许可信息。
- `license_url`：许可说明链接。
- `download_url`：实际下载地址，仅用于本地缓存。
- `width`、`height`、`duration`、`fps`：基础媒体信息。
- `query`：触发该素材命中的搜索词。
- `local_path`：素材在本地存储的路径

合成结果页需要提供“素材来源清单”，即使素材平台不强制署名，也应让用户能查看和导出来源信息。

## 4. 推荐产品流程

1. 用户进入字幕工具，上传“固定图片 + 配音”视频。
2. 用户点击“生成字幕”，系统产出字幕段落并保存到 `projects.result.subtitle_session`。
3. 用户点击“生成补画面方案”，系统基于字幕段落生成镜头计划。
4. 系统按镜头计划调用素材 Provider 搜索候选视频，并展示每个镜头的候选素材。
5. 用户可以预览候选、替换素材、锁定素材、跳过某个镜头或调整关键词。
6. 用户点击“自动合成”，系统下载并转码素材，按字幕时间轴裁剪 B-roll。
7. 系统使用原视频音轨作为主音轨，按配置决定是否烧录字幕，输出新 MP4。
8. 用户在项目记录中恢复该工作区，继续替换素材或重新合成。

## 5. 实现边界与模块归属

该功能优先放在业务层聚合，不直接扩张底层视频引擎的职责。原因是素材搜索、候选选择、授权追溯、页面确认都属于当前业务流程；底层引擎只需要提供可复用的裁剪、转码、拼接、音轨合成能力。

建议新增模块如下：

```text
backend/
├── api/
│   └── broll_api.py                 # 补画面业务 API
├── services/
│   ├── broll_service.py             # 镜头计划、候选选择、任务编排
│   └── stock_video/
│       ├── base_provider.py         # 素材 Provider 抽象
│       ├── pexels_provider.py       # Pexels 视频搜索
│       └── pixabay_provider.py      # Pixabay 视频搜索
│       └── xxxx_provider.py         # 其它可以使用的素材库，按需扩展 视频搜索
├── engine/
│   └── broll_composer.py            # B-roll 裁剪、转码、合成
└── utils/
    └── license_manifest.py          # 素材来源清单生成

frontend/
├── templates/
│   └── subtitle_tool.html           # MVP 阶段直接集成补画面入口
└── static/
    └── js/
        └── broll-workspace.js       # 镜头计划、候选预览、合成任务轮询
```

后续如果补画面成为独立主流程，再拆出 `broll_builder.html` 页面；MVP 阶段先复用字幕工具页，降低导航、状态恢复和项目管理成本。

## 6. 数据落点设计

MVP 不新增业务表，优先复用现有 `projects`、`materials`、`tasks` 三张表：

- `projects.type`：继续使用 `subtitle`，或新增 `broll` 作为独立项目类型；MVP 推荐复用 `subtitle`，避免同一视频在两个项目间割裂。
- `projects.result.broll_session`：保存补画面工作区状态，包括镜头计划、候选素材、用户锁定选择、合成配置和导出结果。
- `materials`：保存已下载的远程视频素材，`type='video'`，`metadata` 中写入素材来源、许可、搜索词、镜头 ID、缓存状态。
- `tasks.type`：新增 `broll_plan`、`broll_search`、`broll_download`、`broll_compose` 等任务类型。

`broll_session` 建议结构：

```json
{
  "version": 1,
  "source_project_id": "项目ID",
  "source_video_path": "uploads/subtitle_videos/demo.mp4",
  "audio_mode": "keep_original",
  "subtitle_mode": "burned",
  "aspect_ratio": "16:9",
  "providers": ["pexels", "pixabay"],
  "shots": [
    {
      "shot_id": "s001",
      "start": 0.0,
      "end": 4.2,
      "duration": 4.2,
      "subtitle_text": "这一刻，城市的节奏开始加快",
      "keywords": ["城市", "节奏", "街道", "人流"],
      "search_queries": ["city street crowd", "urban traffic"],
      "locked": false,
      "selected_candidate_id": "",
      "candidates": []
    }
  ],
  "rendered_video_url": "",
  "license_manifest_url": "",
  "updated_at": "2026-05-27T00:00:00"
}
```

这个落点属于业务聚合层状态，不适合先做成通用中台表。只有当后续需要跨项目素材库、素材收藏、授权审计、批量检索和高频筛选时，再考虑新增 `stock_materials` 或 `material_sources` 表。

## 7. API 设计草案

```text
GET  /api/broll/session/<project_id>
POST /api/broll/session/<project_id>
POST /api/broll/plan-task
POST /api/broll/search-task
POST /api/broll/download-task
POST /api/broll/compose-task
GET  /api/broll/providers
GET  /api/broll/license-manifest/<project_id>
```

接口职责：

- `session`：读取或保存补画面工作区。
- `plan-task`：根据字幕生成镜头计划，不触发远程下载。
- `search-task`：按镜头计划搜索候选素材，只保存候选元数据。
- `download-task`：下载用户选定或系统推荐素材，并写入 `materials`。
- `compose-task`：按时间轴合成新视频，输出视频 URL 和来源清单。
- `providers`：返回素材源配置状态、可用性和缺失配置提示。
- `license-manifest`：导出本项目使用过的素材来源清单。

所有长耗时操作都应走任务接口，前端通过 `/api/tasks/<task_id>` 轮询进度，避免页面请求超时。

## 8. 核心算法与任务流程

### 8.1 镜头计划生成

- 输入：字幕段落、原视频时长、目标比例、用户主题词、禁用词。
- 处理：合并过短字幕段，拆分过长字幕段，提取关键词，生成中英文搜索词。
- 输出：`shots[]`，每个镜头包含开始时间、结束时间、字幕文本、搜索词和期望素材约束。

### 8.2 素材搜索与评分

- Provider 返回结果先统一成内部候选结构。
- 基础评分维度：关键词命中、时长是否足够、分辨率、横竖屏比例、素材源优先级、是否重复。
- MVP 使用规则评分即可；后续可接 CLIP 图文相似度、本地视觉标签和用户历史选择做重排。

### 8.3 下载与缓存

- 相同 `provider + source_id + quality` 的素材只下载一次。
- 下载前检查大小、时长、格式和剩余磁盘空间。
- 下载后统一转为项目可合成格式，例如 H.264 + AAC 或无音轨 MP4。
- 缓存路径建议放在 `uploads/stock_videos/` 或 `temp/stock_videos/`，最终被项目使用的素材登记到 `materials`。

### 8.4 视频合成

- 对每个镜头按时长裁剪素材，素材不足时可循环、慢速拉伸或回退到原画面。
- 根据目标比例执行居中裁剪、留边模糊背景或等比缩放。
- 主音轨默认使用原视频音频，不使用素材自带声音。
- 字幕烧录复用现有字幕渲染能力；如果用户关闭字幕，则只输出 B-roll + 原音频。
- 合成完成后写入 `projects.result.broll_session.rendered_video_url`。

## 9. 前端交互计划

MVP 阶段在 `subtitle_tool.html` 增加一个“补画面”工作区：

- 顶部展示素材源配置状态，缺少 API Key 时给出设置入口。
- 字幕生成后显示“生成补画面方案”按钮。
- 镜头计划以列表展示：时间段、字幕文本、关键词、候选视频、当前选择。
- 每个镜头支持预览候选、替换、锁定、跳过和重搜。
- 底部提供合成配置：画面比例、字幕模式、素材源优先级、最大下载清晰度。
- 合成任务显示进度、当前阶段、失败原因和导出入口。

增强版再补充：

- 批量锁定高分素材。
- 一键重搜低匹配镜头。
- 来源清单查看与复制。
- 缓存清理和素材复用提示。

## 11. 分期里程碑

### 阶段 0：需求确认与接口定稿（0.5-1 天）

- 确认素材源范围、目标视频比例、是否默认烧录字幕、是否允许自动下载。
- 确认 MVP 只接 Pexels/Pixabay，还是先接其中一个。
- 确认补画面入口放在字幕工具页，还是单独页面。

### 阶段 1：MVP 后端链路（4-6 天）

- 新增 `broll_api.py`、`broll_service.py`、Provider 抽象和 Pexels/Pixabay Provider。
- 实现字幕到镜头计划的转换。
- 实现候选搜索、候选归一化、规则评分和会话保存。
- 实现下载缓存和素材表登记。

### 阶段 2：MVP 合成链路（3-5 天）

- 新增 `broll_composer.py`，封装裁剪、转码、拼接和原音频合成。
- 输出合成视频和素材来源清单。
- 完成任务进度更新和失败回退。

### 阶段 3：前端工作区（4-6 天）

- 在字幕工具页增加补画面入口、镜头计划列表、候选预览和合成配置。
- 接入任务轮询、会话恢复和导出结果展示。
- 处理缺少 API Key、搜索无结果、下载失败等空状态。

### 阶段 4：验证与体验打磨（2-4 天）

- 用短视频、长音频、固定图片视频、无字幕视频分别验证。
- 优化候选排序、关键词提取、比例裁剪和错误提示。
- 补充自动化测试和手工验收清单。

## 12. 风险与应对

- **API 限流风险**：Provider 层实现限流、超时、重试和降级；搜索结果做缓存。
- **素材不匹配风险**：MVP 提供候选替换和关键词重搜；增强版引入 CLIP 重排。
- **下载失败风险**：单素材失败不终止整条流程，回退到下一个候选或原始画面。
- **视频比例不一致风险**：提供居中裁剪、留边背景和等比缩放三种策略。
- **合成耗时风险**：全部长耗时步骤走任务表，前端轮询进度；后续可接队列和并发下载。
- **缓存膨胀风险**：按项目大小和缓存天数清理；素材被项目引用时不自动删除。
- **语义提取质量风险**：先用规则和 LLM 可选增强；没有 LLM 时仍可从字幕关键词生成搜索词。

## 13. 验收标准

MVP 完成后至少满足：

- 已有字幕项目可以一键生成镜头计划，镜头时间覆盖原视频有效字幕时长的 95% 以上。
- 每个命中素材都保存 `provider`、`source_id`、`source_url`、`author`、`license` 和 `query`。
- 缺少 Provider API Key 时，前端能明确提示并阻止远程搜索任务。
- 搜索任务、下载任务、合成任务均可通过 `/api/tasks/<task_id>` 查询进度和失败原因。
- 合成视频时长与原视频时长误差不超过 0.5 秒，原始配音音轨完整保留。
- 用户刷新页面后，可以恢复镜头计划、候选选择、合成配置和导出结果。
- 不存在无授权全网爬取逻辑，不保存来历不明的远程素材。

## 14. 测试计划

- 单元测试：字幕分段合并、关键词提取、候选评分、Provider 响应归一化。
- API 测试：会话读写、计划任务、搜索任务、下载任务、合成任务、Provider 配置缺失。
- 合成测试：短视频、长视频、横屏、竖屏、素材不足、无搜索结果、下载中断。
- 前端手工测试：刷新恢复、候选替换、锁定素材、任务失败重试、来源清单展示。
- 回归测试：字幕工具原有生成、编辑、渲染、项目记录恢复功能不受影响。
